# Phase 2 · Oritong 的个人互联网空间

初版设计日期：2026-09-26。依据：Phase 1 审查及现有 `content.js`。本方案已按后续“科技风 + 鼠标星星拖尾”要求更新，设计不依赖图片视觉分析或生成图片。

## 定位与访问路径

这是一个持续整理的个人空间。访问顺序是：认识哦里冻 → 了解正在做什么 → 查看作品介绍 → 按兴趣进入 Wiki。保留原有全部内容、外链、图片引用与有效 Hash 路由。

身份只使用已有信息：哦里冻 / ORITONG、Minecraft 整合包制作者、Blophy 官方谱师，以及现有个人介绍。项目只使用个人档案站和钻石大陆加豪版，不添加经历、技能、成绩、虚构日期或未提供的下载地址。

## 视觉方向

以“星间的个人空间”为方向：午夜蓝背景、冰青链接、少量浅紫注记。科技感来自静态细网格、几何头像框、面板边线、等宽注记和有明确层级的排版。保留作者原本的语气、头像和图库，不添加虚构系统状态或项目数据。图片只沿用已有引用，不凭文件名猜测画面。

首页有呼吸感，文档区更紧凑；统一颜色、字体、边框、按钮和链接。细网格仅在 Hero 内，Wiki 正文保持纯色。背景星空、低频随机流星与鼠标五角星拖尾默认开启；背景和拖尾可独立切换并记住选择，减少动态偏好优先。背景关闭且拖尾消退后停止请求动画帧，不加入旋转轨道或大型动态装饰。

## 页面方案

- **Header**：Oritong / 哦里冻；首页、项目、Wiki、关于、资源、图库；搜索。当前页有明确文字/下划线状态。手机使用可关闭的导航面板，关闭时不可聚焦，支持 Escape、焦点恢复和背景滚动管理。
- **首页**：姓名 Hero + 已有简介/身份 + 关于入口；“这段时间”列出现有维护状态；精选只展示钻石大陆，提供全部项目入口；移除项目旁重复的个人引言，单个项目铺满该行；Wiki 为次级但清楚的入口；资源与图库作为个人收藏入口；已有社交链接。
- **项目列表**：统一 Project Card，包含类型、状态、名称、简介、标签、“了解项目”和可选 Wiki。没有真实 URL 就不显示 GitHub/下载按钮。
- **项目详情**：新增 `#/projects/:id`，先说明项目、角色、记录成果，再显示文档章节与已有外部入口；允许项目没有 Wiki。
- **Wiki 首页**：`#/wiki`，按真实项目显示文档数量与章节；本站维护文档与作品资料使用相同组件。
- **Wiki 文章**：面包屑 + 左侧项目目录 + 约 68ch 的阅读区；长篇才显示页内目录；标题、段落、警告、代码块；上一篇/下一篇。手机目录折叠为原生 details。只在有数据时显示适用版本/更新日期。
- **关于**：保留全部已有介绍、8 个社交主页和 2 个群号；统一链接样式与复制反馈。
- **资源**：保留 12 条和分类过滤；搜索结果直达具体条目；分类与当前项有明确状态。
- **图库**：保留 6 条图片、alt、署名、画师链接、使用声明、图片防拖动功能；展示区域为图片预留固定比例，以 contain 保留完整画面；不添加下载功能，也不修改图片文件。
- **Footer**：姓名与已有身份、项目/Wiki/关于链接、已有社交主页、版权、低优先级部署指南和外观设置。

## Design System

### 颜色

| Token | 值 | 语义 |
| --- | --- | --- |
| Primary | `#82e5f5` | 冰青链接、主按钮 |
| Secondary | `#b9acfa` | 浅紫次级注记 |
| Background | `#080f1c` | 午夜蓝页面背景 |
| Surface | `#0e1a2c` | 导航、阅读表面 |
| Card | `#122139` | 卡片 |
| Text | `#edf5ff` | 正文 |
| Muted | `#afbdd2` | 辅助文字 |
| Border | `#30455f` | 面板分隔 |
| Accent | `#b9acfa` | 少量重点提示 |
| Hover | `#1a2f48` | 交互悬停 |
| Active | `#203951` | 当前导航/筛选 |

文档采用同一暗色语言，替换单个项目白底硬编码；不再分别维护两套互相覆盖的正文颜色。焦点使用高可见的 Primary 轮廓。正式验收计算正文与常用表面的对比度。

### 字体

沿用 DM Sans / Noto Sans SC，代码、短注记和项目状态使用 DM Mono / 系统 monospace；有系统回退。

| 层级 | 尺寸 | 行高 | 字重 |
| --- | --- | --- | --- |
| Display | 48–88px，随视口变化 | 1.15 | 600 |
| H1 | 32–48px | 1.3 | 600 |
| H2 | 24–32px | 1.4 | 600 |
| H3 | 20–24px | 1.45 | 600 |
| Body | 16px；Wiki 17px | 1.75；Wiki 1.9 | 400 |
| Small | 14px | 1.6 | 400/500 |
| Caption | 12px | 1.6 | 500 |
| Code | 14px | 1.75 | 400 |

正文不加字间距；短英文注记可用轻微字距；不在中文段落使用大写风格。Wiki 段落间距 24px，分节间距 48px。

### 尺寸

- Spacing：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px。
- Radius：按钮/输入框/徽章/头像 4px，卡片与弹出面板 12px；不创建不需要的 Modal。
- Shadow：常规卡片无外阴影；悬停/键盘聚焦以青色内侧边线提示，搜索弹层保留轻微阴影。
- 内容容器最大 1160px，左右留白 24px（小屏 16px）；Wiki 容器最大 1280px；主要交互触控区域至少 44px。

## 响应式与可访问性

宽屏：首页两列 Hero、项目两列、Wiki 侧栏 224px + 正文。小于 960px Header 折叠，Wiki 目录折叠；小于 640px Hero/项目/图库均一列，操作按钮换行、所有标题可完整换行，代码区域自身滚动。避免固定高度剪裁正文，避免用缩小到 7–10px 的文字来适配手机。

使用 header/nav/main/article/aside/footer、每页一个 H1、按序标题、跳至正文、aria-current、原生 button 与 link 区分、明确的输入框标签、搜索结果键盘操作、群号复制反馈。通过精简 live region 宣告切页，不朗读整篇文章。

界面交互用 160ms 的颜色、边框过渡；鼠标拖尾最多 28 颗五角星，每颗在 0.8 秒内消退，颜色直接读取 CSS Token。鼠标停止且星星消退后不持续绘制；触屏不触发拖尾，不拦截任何指针操作。系统减少动态时取消动画与过渡，星空和指针拖尾均不运行。
